# 從網頁新增裝置

日期：2026-10-13。此功能從已設定的 Home Assistant 匯入實體，不會掃描網路或代替品牌配對。

## 使用方式

1. 先在 HA 加入設備整合，確認能讀取真實狀態。
2. 後端 `.env` 設定 `HUB_MODE=real`、`HA_URL`、`HA_TOKEN`，重新啟動。`HUB_MAPPING_FILE` 可留空；已有專屬映射可繼續使用，不會被精靈修改。
3. 以平台管理員登入，在總覽或裝置管理按「新增裝置」。
4. 在「可加入」勾選實體，設定裝置名稱與房間。第一版每個 Entity 建立一張卡片；不會依品牌或名稱猜測多實體合併。
5. 預設「僅查看，鎖定控制」。感測器與尚未驗證控制的裝置可直接唯讀匯入。
6. 若要開放 light／switch 的基本開關，取消鎖定，親自確認負載可以安全切換，再逐次按「測試開啟」「測試關閉」。測試會立即操作電器，不自動恢復原狀，請自行恢復需要的狀態。
7. 兩個方向都收到 HA 新目標狀態後，勾選「匯入後開放基本開關控制」，十分鐘內完成匯入。只收到 service 接受、沒有新狀態，不算成功。
8. 檢視內容後按「加入」。卡片及房間會更新，不需要修改 Entity ID 設定檔。

路由器、電腦總電源等重要負載請維持鎖定。已映射實體不允許從精靈測試或重複匯入，不能用此功能繞過既有保護。HA 新狀態確認是整合回報驗證，不是額外硬體量測。

## 支援範圍

| 類型 | 本版匯入能力 |
| --- | --- |
| light、switch | 開關狀態；雙向測試後可選擇基本開關控制 |
| sensor | 溫度 °C、濕度 %、電量 %、功率 W；需 HA 正確提供 device_class 與單位 |
| camera | 連線／狀態；串流、隱私、PTZ 不會自動開放 |
| fan、humidifier、climate、remote、select、number 等 | 顯示待支援，保留目前的專用整合 |

未知單位、未知類型與進階控制不會產生虛假控制按鈕。既有檯燈調光、攝影機、香氛機、除濕機及 IR 專屬介面繼續沿用原映射。多整合產生不同 Entity 但實際是同一設備時，本版無法自動辨認，請只選一個來源。

此精靈依 Entity 類型與 HA 回報能力判斷，不以 Tapo、小米或本專案實測型號作為允許清單。其他廠商只要透過 HA 提供相同的支援類型與單位，也能使用此流程。品牌專屬配對及進階控制仍由相容整合負責，不能保證所有產品都可控制。

開關測試另查詢 HA Entity Registry：設定／診斷、停用、隱藏或分類無法確認的實體不開放測試。自動更新、自動關閉、韌體、重啟、隱私、偵測與童鎖等設定，即使整合未標記分類，也只允許唯讀匯入；不能透過精靈改變受保護插孔的排程行為。

## 持久化與部署

匯入映射寫入目前模式的 SQLite `imported_devices` 資料表，批次交易與唯一鍵防止重複，重啟會恢復。Mock 與 Real 記錄隔離；Mock 候選、測試及控制全部是示範。十分鐘測試證明只在後端記憶體，重啟會清除；已完成匯入的控制設定會保存。

備份／移植時需保留 SQLite 資料庫及自己的私有設定。使用單一後端 worker；本版不支援多程序即時重新載入映射。現有私有 JSON 映射優先，衝突實體不從資料庫再次加入。HA Token 僅在後端，候選回應不包含原始屬性及影像 URL。

所有精靈端點僅管理員可用，寫入需要 Session、CSRF 與來源驗證。離線候選可以唯讀加入；開關測試不可離線執行。沒有出現在列表的設備，需要先完成 HA 整合或確認是否屬於本版候選類型。
